# StandEL Time v0.9 — Material / Dagbok / ÄTA

## Установка

1. Используйте копию ранее подготовленного проекта v0.8.
2. В тестовом Supabase, где успешно выполнены `sql/001_schema.sql` и `sql/002_work_orders.sql`, примените **один раз** `sql/003_material_diary_ata.sql` через SQL Editor. Предварительно сохраните резервную копию и не применяйте миграцию в рабочей базе без аудита RLS.
3. В корне проекта выполните `npm install`, `npm run typecheck`, `npm run build`. Нужны корректные `.env` из `.env.example` и активный проект Supabase.
4. Запустите `npm run dev`; откройте `/admin` или `/employee` после входа. Политики RLS разрешают чтение только участникам организации.
5. На хостинге разместите тот же репозиторий как Next.js-приложение; домен `time.standel.se` подключается отдельно через DNS one.com.

## Модули

- **Материалы**: сотрудник записывает материал, единицу, количество, дату, проект и необязательный Arbetsorder. Администратор видит все записи и может отдельно назначить закупочную цену и стоимость для клиента. Цены хранятся в `material_prices`, к которой работникам нет доступа.
- **Dagbok**: рабочие дневники с описанием и заметками по безопасности; одна фотография JPG/PNG/WebP до 10 МБ на запись через приватный Supabase Storage. Фотографии выдаются через короткоживущие подписанные ссылки. Пользователь видит свои записи, администратор — всю организацию. Если загрузка фото не прошла, дневник всё равно сохранится.
- **ÄTA**: работник отправляет запрос о дополнительных работах с оценкой часов. Администратор согласует или отклоняет внутри StandEL и может ввести стоимость труда, материалов и иных работ в закрытом разделе `ata_finance`.

**Важно**: Внутреннее согласование ÄTA не заменяет согласования заказчика, не формирует счёт и не означает оплаты. Фотографии и дневники не являются официальными протоколами испытаний электроустановок.

## Безопасность и границы текущей версии

- SQL RLS и серверная проверка ролей — проектное решение, не проведён независимый аудит.
- Приложение ещё не развёрнуто; миграция, email/SMS и загрузка с телефонов не проверены на реальном Supabase.
- Не подключены уведомления, полноценный офлайн-режим, пересчёт НДС, экспорт фактур, каталог материалов и договорные тарифы ÄTA.
- Типы часов OB / övertid из предыдущей версии не рассчитывают автоматически надбавки Installationsavtalet.
- Не загружайте персональные данные работников и конфиденциальные фотографии до тестирования доступа с двумя учётными записями.

## Быстрый тест после развёртывания

1. Администратор создаёт объект и назначает электрика.
2. Создаёт Arbetsorder и назначает электрика на него.
3. Электрик входит под **другим** аккаунтом, добавляет запись Material, Dagbok с фотографией и запрос ÄTA.
4. Электрик перезагружает страницу: данные должны восстановиться из Supabase.
5. Администратор видит те же записи, ставит цену на материал, оценивает и согласует ÄTA.
6. Сотрудник **не** должен видеть закупочную цену, клиентскую ставку или чужие записи.
7. Проверить фото: чужой аккаунт не должен скачивать приватные файлы; доступ администратору должен работать через подписанную ссылку.
8. Проверить попытку изменить project_id на чужой объект напрямую через Supabase API — операция должна завершиться ошибкой.
