# StandEL Time v0.8 — Arbetsorder

## Что нового

- Администратор видит раздел **Arbetsorder**, создаёт рабочие задания в рамках существующих проектов, устанавливает номер, название, описание, приоритет и срок.
- Задание можно назначить нескольким электрикам, которые уже закреплены за этим объектом.
- Работник видит только свои задания и может переводить их по цепочке **open → in_progress → done**.
- Администратор может подтвердить выполненное задание (**done → approved**) или вернуть в работу. Он также может отменить открытое/выполняемое задание.
- При внесении часов сотрудник может выбрать конкретный Arbetsorder или оставить учёт без задания. Запись часов по чужому заданию отклоняется базой данных.
- В CSV-отчёте администратора и списке часов добавлен номер задания.
- Изменения заданий и назначений попадают в общий журнал audit_events.

## Как перейти с v0.7 на v0.8

1. Создать резервную копию базы Supabase; проверить, что уже применён `sql/001_schema.sql`.
2. В Supabase SQL Editor применить **только** `sql/002_work_orders.sql`, не повторять `001_schema.sql` в действующей базе.
3. Обновить код на Vercel, настроить переменные из `.env.example`, перезапустить deployment.
4. Администратор создаёт проект, назначает работника на проект в разделе «Графики», затем создаёт Arbetsorder и назначает исполнителя.
5. Работник заходит в `/employee`, видит задание и может начать его; при отчёте часов указывает объект и номер задания.
6. Проверить фактическое сохранение после обновления страницы и проверку прав доступа на двух отдельных учётных записях.

## Условия безопасности

- `work_orders` и `work_order_assignees` защищены RLS.
- Статусы изменяются по RPC `set_work_order_status` с проверкой назначения и допустимого перехода.
- Сотрудник не может создавать задание, назначать других сотрудников или видеть чужие задания.
- Созданный номер задания и его проект нельзя менять, чтобы история отчётов оставалась однозначной.
- Нельзя назначить человека на Arbetsorder, пока он не назначен на проект.

## Что пока НЕ реализовано

- Фото, документы, материалы и ÄTA (планируется v0.9).
- Реальные отправки push-уведомлений о новых заданиях.
- Автоматическое фактурирование по Arbetsorder.
- Полное E2E-тестирование с действующим облачным проектом Supabase: требуются настроенные аккаунты и тестовые пользователи.
- Компоненты v0.7 ещё имеют отдельные незавершённые функции (в частности таймер, локализации всех экранов, цветной Excel) и не должны использоваться как производственный табель до проведения проверки.

## Обязательные тесты перед эксплуатацией

1. Администратор создаёт объект и назначает двух работников.
2. Администратор создаёт Arbetsorder с двумя исполнителями; они видят одно и то же задание.
3. Работник, не включённый в задание, не видит его и не может связать с ним свои часы даже через API.
4. Назначенный работник меняет `open` → `in_progress` → `done`, после чего администратор меняет `done` → `approved`.
5. Работник не может назначить исполнителей, изменить название/проект или подтвердить задание как администратор.
6. Отработанные часы появляются в отчёте с номером задания после перезагрузки.
7. Попытка привязать часы к Arbetsorder из другого проекта отклоняется.
8. Два одновременных изменения статуса проверяются на конфликт; факт изменения и автор видны в `audit_events`.
9. Неактивному сотруднику закрыт доступ к чужим заданиям.
