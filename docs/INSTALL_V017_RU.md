# StandEL Time Online v0.17 — инструкция обновления

## Что появилось

1. Вход по email и собственному паролю (Supabase Auth). Для уже существующих аккаунтов: «Установить пароль» → одноразовый email-код → новый пароль. Для восстановления — «Забыли пароль?» → email-код → новый пароль. Новые приглашённые работники устанавливают пароль после подтверждения персональной ссылки `/join`.
2. Выбранный объект хранится в **localStorage данного браузера** по ID пользователя и организации. Выбор сохраняется до смены объекта, если работник продолжает быть назначен на него. При использовании другого устройства объект потребуется выбрать снова.
3. Календарь сотрудника с суммой по дням и месяцам, деталями и исправлением/архивированием часов. История изменений фиксируется существующей таблицей `audit_events`.
4. Администратор утверждает месячный табель **конкретного сотрудника за весь месяц по всем объектам**. Повторное открытие разрешено администратору. Триггер PostgreSQL предотвращает insert/update/delete часов за утверждённый месяц независимо от клиента.
5. Запрещается создавать НОВУЮ организацию с существующим регистрационным номером. Старые дубли не удаляются автоматически.

## ВАЖНО: установка только после резервной копии

1. До обновления выгрузите резервную копию Supabase, в частности `organizations`, `org_members`, `projects`, `project_assignments`, `time_entries`, `absences`, `audit_events`.
2. Убедитесь, что на текущей базе успешно выполнены `001_schema.sql`, `002_work_orders.sql`, `003_material_diary_ata.sql`, `004_online_reports_absences.sql`.
3. На резервной/тестовой базе **первым** выполните **только** `sql/005_password_calendar_payroll.sql`. Не выполняйте повторно 001–004. Проверьте появление `public.payroll_months` и отсутствие ошибок.
4. Загрузите файлы этого архива в корень **Private** GitHub репозитория `StandELAB/standel-time`, сохранив переменные окружения только в Railway. Не загружайте `.env.local`, SMTP-пароли и Supabase secret key.
5. Railway должен пересобрать Next.js. Проверьте Deployments и статус Active. При ошибке — Build Logs, не применяйте миграцию повторно без анализа.
6. Supabase → Authentication → Providers → Email: убедитесь, что вход по email разрешён, SMTP работает и шаблон Magic link or OTP содержит `{{ .Token }}`. Для входа через пароль отдельный код не нужен.
7. Выполните тесты под двумя тестовыми учётными записями (admin и employee), а не под реальными работниками.

## Контрольный тест

- Работник → Вход → Установить пароль → email-код → пароль 12+ символов → Выйти → обычный вход email + пароль.
- Сотрудник меняет объект и обновляет страницу: выбор сохраняется на данном устройстве.
- Сотрудник записывает часы, открывает «Мой календарь», исправляет время и описание. В `audit_events` появляется действие `update`.
- Админ → «Часы работников» → месяц → «Утвердить месяц» для тестового работника. Сотрудник больше не может добавить, исправить или удалить запись в этом месяце, даже в старой открытой вкладке.
- Админ нажимает «Открыть месяц»: сотрудник снова может редактировать. В `audit_events` остаются события `approve` и `reopen`.
- Проверьте, что существующие часы и назначения сохранены.

## Ограничения перед производственным использованием

- В этой версии не проведена реальная сквозная проверка на вашем Railway и Supabase. Исходники проверены на синтаксис; успешная сборка Next.js не подтверждена.
- Кабинет сотрудника первоначально загружает до 200 записей часов; администратор — до 500. Для больших исторических периодов нужна серверная пагинация, иначе месячные суммы могут быть неполными.
- Функция сохранения последнего объекта работает на конкретном устройстве; синхронизация предпочтения между устройствами ещё не сделана.
- Email OTP в режиме восстановления фактически даёт возможность сменить пароль при доступе к почте; защитите почтовые ящики и настройте лимиты запросов.
- Двухфакторная аутентификация администратора, полноценные XLSX, аватарки и назначение прав на вкладки остаются отдельными задачами.
- Миграцию не следует запускать на живой базе, не протестировав сначала на копии; для отката требуется проверенный план и резервная копия.
