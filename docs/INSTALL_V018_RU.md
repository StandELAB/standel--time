# Установка StandEL Time Online v0.18

Текущая работающая версия: **v0.17**. Обновляем поверх неё, без сброса таблиц и данных.

1. В Supabase подготовить отдельный **тестовый проект**, где уже есть миграции 001, 002, 003, 004 и 005. Проверить резервную копию и план отката.
2. В Supabase → SQL Editor → New query вставить **полный текст `sql/006_profiles_features.sql`**. Run. **НЕ выполнять предыдущие миграции повторно**.
3. Проверить:

```sql
select table_name from information_schema.tables
where table_schema='public'
and table_name in ('profile_avatars','employee_feature_access');

select id, name, public from storage.buckets where id='standel-avatars';
```

Ожидаемый результат: две таблицы и бакет со значением `public = false`.

4. В тестовом GitHub-репозитории поверх кода v0.17 скопировать файлы v0.18 и отправить commit. Секретные ключи остаются только в Railway.
5. Убедиться в `Success / Active` нового развёртывания. Войти под admin/foreman/employee и пройти сценарии из `README_RU.md`.
6. В рабочей среде повторить миграцию/развёртывание **только после проверки на копии**. Наблюдать ошибки RLS, авторизации и сохранения часов.

**Отдельно о ролях:** бригадир назначается администратором в разделе «Работники / доступ». Администратор сначала меняет роль работника на «Бригадир», затем выбирает этого бригадира у электриков. Сотрудники не могут назначить себя бригадирами или обойти управление вкладками через API.

**При сбое:** не удалять таблицы, не отключать RLS; сверить Deploy Logs, вернуться к предыдущему рабочему коммиту и использовать заранее проверенный план восстановления данных при необходимости.
