# StandEL Time v0.38 — SMS и email напоминания

Обновление поверх v0.37. Оба канала подключены к серверу: Resend (email) и Twilio (SMS). Новая панель расположена в «Контроль табелей» администратора.

## До загрузки на Railway

1. Изучить `sql/012_reminder_delivery.sql`, применить в **рабочем** Supabase SQL Editor (желательно сначала сделать резервную копию). Создаётся `reminder_deliveries` с ограничением одной записи на работника/дату/канал. Простые пользователи не имеют доступа к этой таблице.
2. Загрузить содержимое архива в репозиторий, `Commit to main` → `Push origin` → Railway Success/Active.
3. В Railway Variables: `RESEND_API_KEY` (уже используется для приглашений), `INVITE_FROM_EMAIL=StandEL Time <noreply@standel.se>`, `APP_URL=https://time.standel.se`. Для SMS потребуются `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER` (провайдер Twilio, оплачивается отдельно). Не публикуйте ключи в чате.
4. Сотрудник должен заполнить email и номер телефона в формате E.164 (`+46...`) в личных данных. Если контакта нет, кнопка канала недоступна.

## Безопасный запуск

- Сначала проверить на двух тестовых сотрудниках, у которых есть **смена в графике на прошедшую дату** и нет записи часов/подтверждённого отсутствия. Подтвердить вручную отправку одного email, затем SMS.
- По умолчанию автоматическая рассылка **выключена**. Запуск `POST /api/cron/reminders` требует заголовка `Authorization: Bearer <REMINDER_CRON_SECRET>` и переменной `REMINDERS_ENABLED=true`, а также обязательной `REMINDER_ORG_ID` (UUID вашей организации).
- Для расписания создайте отдельный планировщик HTTP, который отправляет этот POST в 09:00 Europe/Stockholm каждый день (учесть зимнее/летнее время). Простой Railway Cron в UTC без DST-адаптации будет менять местное время срабатывания. Не ставьте расписание до проверки ручной отправки и согласования правил компании.
- Автоматическая отправка обрабатывает **вчерашние** смены и только при явном включении. В проекте не создаётся самостоятельное расписание Railway.

## Ограничения

- Провайдеры принимают запросы, но факт доставки до устройства/ящика отдельно не подтверждается; вебхуки статусов пока не реализованы.
- При ошибке отправки запись помечается `failed`, повторная отправка того же дня/канала пока блокируется. Повтор требует отдельного безопасного административного механизма, а не удаления строк SQL вручную.
- Если часы ещё не внесены, но смена фактически отменена без отражения в системе, возможно ложное напоминание. Вручную проверить список перед отправкой.
- Не отправляются медицинские причины отсутствий или другая чувствительная информация. Нет сообщений сотрудникам без запланированных смен.
- Перед регулярной рассылкой организуйте резервное копирование базы и порядок управления согласиями/контактами сотрудников.

**SQL 012 обязательна.** Сборка Next.js и реальная отправка требуют проверки в твоей среде (API ключи не включены в архив).
