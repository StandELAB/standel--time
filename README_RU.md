# StandEL Time v0.30 — сотрудник самостоятельно выбирает объект

Основа: исходники v0.29. Миграция `sql/011_employee_project_self_selection.sql`.

## Изменения
- Электрик или бригадир видит **все действующие объекты своей организации** без назначения администратором.
- При выборе объекта создаётся запись в `project_assignments` от собственного имени. Выбор сохраняется в Supabase **до регистрации часов** и остаётся в списке объекта у администратора.
- Администратор → Объекты: под объектом показаны только сотрудники, выбравшие его. Кнопка «Обновить список сотрудников» подтягивает последние выборы без перезагрузки страницы.
- Никаких изменений в механизме сохранения, редактирования, аудита или утверждения часов. Обычные работники не получают доступ к часам коллег.
- Архивные объекты не доступны для нового выбора. Старые часы и история выбора сохраняются.
- На одном дне можно сохранить разные записи на разных объектах, пока время не пересекается.

## Установка
1. Перед миграцией рекомендуется резервная копия Supabase; она пока не настроена.
2. В **рабочем** Supabase SQL Editor запустить `sql/011_employee_project_self_selection.sql`.
3. Заменить файлы репозитория в GitHub Desktop; Commit / Push main.
4. Убедиться, что Railway показывает Success / Active.
5. Под тестовым электриком выбрать ранее не назначенный действующий объект. **До сохранения часов** открыть админку и нажать «Обновить список сотрудников» — тестовый электрик должен появиться под объектом.
6. Сохранить тестовую запись часов, проверить, что второй сотрудник по-прежнему не видит её через API.
7. Проверить, что архивный объект не доступен в выпадающем списке.

**Важно:** v0.29 архивирование сотрудников требует отдельно миграции 010, если ещё не выполнена. Миграция 011 не зависит от 010. Архивирование объектов остаётся в v0.28+.

**Ограничение:** запись выбора объекта остаётся исторической, даже если сотрудник позже выбирает другой объект. Это показывает, на какие объекты сотрудник когда-либо записывался; это не отметка присутствия сегодня. Для отчёта фактического присутствия используйте часы за дату.

Никаких изменений `auth.users` или удаления существующих данных.
