# StandEL Time Online v0.19 — первый этап

Обновление поверх v0.18. **Новых миграций SQL нет.**

Добавлено:
- Администратор: вкладка «Контроль табелей» — предварительный список прошедших рабочих дней без часов, с учётом существующих записей смен, назначений и утверждённых/сообщённых отсутствий; фильтр по месяцу и сотруднику; экспорт XLSX.
- Мобильные стили: крупнее поля и кнопки, удобнее прокрутка вкладок на телефоне.

**Ограничения:** контроль табелей использует только записи, переданные сервером на страницу (в v0.18 выборки ограничены). Следовательно, возможны ложные пропуски. Назначение сотрудника на объект не является обязательной ежедневной сменой. Не использовать результаты как доказательство отсутствия или для удержания зарплаты. Автоматическая рассылка напоминаний, полноценный календарь отсутствий и расширенная панель бригадира не входят в этот первый этап.

Порядок: сохранить старый код, заменить содержимое репозитория файлами из архива (не вкладывая дополнительную директорию), Commit + Push. Дождаться Railway Active. Supabase 006 остаётся без изменений. После деплоя проверить «Контроль табелей» и мобильную страницу. **Рекомендуется резервное копирование до развёртывания**, несмотря на отсутствие изменений SQL.

# StandEL Time Online v0.18

Дальнейшее обновление работающей серверной версии StandEL Time v0.17 на Railway и Supabase.

## Добавлено

- Личный аватар пользователя (JPG/PNG/WebP до 2 МБ) в отдельном **закрытом** бакете `standel-avatars` Supabase Storage. Загрузка доступна только самому пользователю. Фото коллег видят только администратор и назначенный бригадир, имеющие доступ к учётной записи.
- Администратор может назначить сотрудника бригадиром, назначить работнику конкретного бригадира и включить дополнительные вкладки отдельным электрикам: Arbetsorder, Material, ÄTA.
- Бригадир видит в разделе «Моя бригада» только сотрудников с `supervisor_id`, равным его `user_id`, и может включать для них дополнительные вкладки.
- Стандартные вкладки электрика: Главная, Мои часы, Dagbok, Календарь; дополнительные скрыты до разрешения. Бригадиру дополнительные рабочие вкладки доступны по роли.
- Основные административные разделы экспортируются в **настоящий Excel .xlsx** (не переименованный CSV). На главной электрика и его доступных вкладках также есть Excel. Для PDF сохраняется режим браузерной печати.
- Доступ к закрытым дополнительным разделам ограничен также в базе **RLS**, а не только интерфейсом. Сотрудник без разрешения не может читать и добавлять Material/ÄTA или читать Arbetsorder. Проверка статуса Arbetsorder по RPC также усилена триггером.

## Порядок обновления

1. **Сделать проверенную резервную копию** Supabase, проверить возможность восстановления. Не обновлять действующую базу без отдельного тестового проекта.
2. Сначала развернуть копию StandEL Time v0.17 в тестовой среде, куда скопированы схема и тестовые данные без лишних персональных данных.
3. На тестовой базе, где уже применены SQL 001–005, выполнить **только `sql/006_profiles_features.sql`**. Он создаёт новую таблицу аватаров, таблицу прав, закрытый бакет, RLS и проверенные RPC.
4. Загрузить содержимое архива в **корень** private GitHub `StandELAB/standel-time`, без `.env.local`, JWT, паролей, SMTP-ключей. Не создавать вложенную папку в репозитории.
5. Railway пересоберёт приложение. Проверить Deployments → Active и диагностические журналы; затем повторить на рабочем проекте по отлаженной процедуре.
6. Тестировать с тремя учётными записями (admin, foreman, employee), а не с действующими рабочими.

## Контрольные тесты

- Администратор видит в «Работники / доступ» работника, назначает ему роль employee, выбирает бригадира из списка и разрешает только `Material`.
- Сотрудник после обновления открывает только «Главная», «Мои часы», «Dagbok», «Календарь» и `Material` — но не `ÄTA` и `Arbetsorder`.
- Бригадир видит назначенного ему работника и может разрешить ему `ÄTA`, но не видит и не изменяет доступ постороннего сотрудника. Проверить RPC напрямую с токеном обычного пользователя: ожидается отказ.
- Сотрудник загружает аватар. Администратор и его бригадир видят фото рядом с именем; посторонний сотрудник не может просмотреть его через Supabase Storage.
- Excel экспорт в каждой доступной вкладке создаёт `.xlsx`, в таблицах верно сохраняются часы и русские буквы; PDF через печать браузера.
- Вновь проверить запись рабочих часов и блокировку утверждённого месячного табеля после обновления.

## Известные ограничения

- Проведена синтаксическая проверка исходников TypeScript/TSX, XML Excel и структуры архива; **полную сборку Next.js и запуск с реальным Supabase/Railway здесь подтвердить нельзя** (недоступен сетевой npm-реестр и подключение к вашей базе).
- Вход по паролю из v0.17 остаётся без изменений; не требуется повторно устанавливать пароль.
- Все выборки часов (лимит 200–500) пока требуют пагинации для полного долгосрочного отчёта; месячные отчёты по большим объёмам могут быть неполными. Перед использованием для зарплат необходима выборочная сверка с базой.
- Экспорт формирует одну таблицу на Excel-лист, без бухгалтерских формул и фирменных шаблонов. PDF — через стандартную печать браузера, не отдельный серверный генератор.
- Аватар после перезагрузки страницы обновляется; для замены уже сохранённой картинки может понадобиться перезагрузить страницу из-за браузерного кеширования.
- Перед открытием для настоящих сотрудников необходимо протестировать RLS и все роли на отдельной базе, сделать backup/restore drill и решить вопросы обработки персональных данных (GDPR).
